# ForgeCommunity competitive benchmark and product priorities

Reviewed 14 October 2026. This compares vendor-documented capabilities and current hosted-plan pages, **not hands-on audits or performance measurements**. Plan entitlements and pricing change. A vendor marketing statement is labeled as such; it is not evidence that a feature works well. ForgeCommunity findings below come from the checked-out repository's source, not the README alone.

## Critical journeys: Forge's current starting point

| Journey | Repository evidence | Recommended outcome |
| --- | --- | --- |
| Join → first value | `app/register`, `app/login`, dashboard and many top-level sections exist; no verified short, guided first-action sequence. | After sign-up, offer a skippable, role-aware checklist: complete profile, pick an interest/skill, join a relevant discussion/course, see one event. Keep empty states actionable ([NN/g](https://www.nngroup.com/articles/empty-state-interface-design/)). |
| Ask → discover → answer | Posts, comments, likes and tags are modeled; `app/community` and `/api/posts` are present. No `Report`/`Flag` model or moderator queue appears in `prisma/schema.prisma`/`app/api`. | Provide descriptive categories/tags, clear post affordance, duplicate suggestions, an answer/solved state where appropriate, reporting and a triage queue. Discourse and Bettermode show why safety cannot rely on an admin user list alone. |
| Enroll → learn → earn | Courses/content/quiz/certificate routes exist, but the course card goes straight to protected content and no enrollment creation path has been found. Course progress is recorded in `app/courses/[courseId]/contents/utils/visitedPages.ts` in localStorage, while `/api/courses/[courseId]/certificate` requires database `Enrollment.completedAt`; no completion write has been found. | Repair enrollment and authoritative, account-specific lesson/quiz completion before expanding rewards. Make certificate issuance idempotent and server-verified. Preserve progress across devices; display why a milestone is locked. |
| Find → RSVP → attend | Event calendar/list and ICS export exist; `EventAttendee` is modeled but no attendee mutation path has been found. | Add transactional RSVP/cancel, capacity/waitlist rules only if needed, time-zone clarity, calendar export and confirmations. Do not award attendance for a mere page view. |
| Find people → connect | Member directory filters skills/roles and profiles/following exist. `/api/search/route.ts` searches `User.email` for any authenticated user even though email is omitted from results. | Remove ordinary member-email search (or admin-scope it) to close membership probing; let members choose profile/discoverability and leaderboard visibility. Preserve useful role/skill filters. |
| Search → navigate | `/api/search` covers course/event/member/post/resource via case-insensitive substring matching. It does not list article/project/skill types in `VALID_TYPES`; `app/search` provides type tabs. | Finish coverage and rank useful exact/title matches, then add clear filters, result counts and zero-result recovery. Keep filter changes stable, per [NN/g's research](https://www.nngroup.com/articles/applying-filters/). |
| Notify → return | Notifications/SSE and persisted email/push settings exist; whether every delivery path honors the settings needs testing. | Group related notifications, link to the exact event/post/lesson, add digest/mute controls and verify preferences are enforced. |
| Admin → keep community healthy | `ADMIN` and `MODERATOR` roles and admin dashboard/user pages exist; no report model or moderation queue has been found. | Build minimal report/triage/resolution/audit flow, role-limited actions and transparent feedback to reporters. Do this before broad public gamification. |

## Gamification: substantial, but tied to real achievement

Forge has `Badge`/`UserBadge` schema and a community leaderboard. No badge award/create flow was found outside deletion on user removal. `/api/leaderboard/route.ts` calculates `endorsements + 10 × posts + 5 × comments`, sorts every user, and publishes the top ten. This rewards volume, has no time window, no quality validation and no visible public-ranking opt-out. Do not present it as a mature reward system.

1. **First repair the source of truth.** Introduce authenticated, idempotent `Enrollment` and per-content completion records. Completion should require a deliberate learner action and/or server-graded quiz, then atomically update course completion, badge eligibility and certificate eligibility. Never use localStorage as the authoritative credential check.
2. **Use two progress tracks.** A private learning journey (lesson/quiz/course milestones, skill path, certificate) and an optional public contribution journey (helpful answers, accepted solutions, peer-endorsed expertise, event participation). Show “what counts” and the next reachable milestone. Keep gamification optional and avoid ranking people by personal learning speed.
3. **Build an auditable reward ledger.** Award once per immutable event key; record event, target, reason, timestamp and reversals. Cap repetitive actions, exclude self-likes/self-endorsements, discount deleted/spam content, withhold uncertain rewards until moderation, and make moderator adjustments reviewable. Circle documents reward logs and reversals; its [point mechanics](https://help.circle.so/p/audience/gamification/get-to-know-gamification) also illustrate limitations worth avoiding (system like-points cannot be disabled and remain after content deletion).
4. **Make badges meaningful.** Start with “First helpful answer,” “Course complete,” “Mentor,” “Event contributor” and one or two domain-specific skill badges; each has a transparent criterion, accessible text label, issuer/date and link to qualifying evidence where public. Discourse's [badge guide](https://meta.discourse.org/t/badges-reference-guide/310717) offers examples, but do not clone sheer volume.
5. **Offer friendly challenges.** Time-boxed cohort/learning challenges with personal progress and community goals; pause or resume without streak shame. Mighty documents live courses/challenges, streaks, recognitions and badge automation on its [pricing/features page](https://www.mightynetworks.com/pricing). Make motion celebratory but nonessential, respecting reduced-motion preferences.
6. **Respect privacy and fairness.** Default learning progress private. Let members hide their public rank and reward history, and exclude staff/test accounts; Circle documents these controls. If enabled, show weekly/monthly/all-time leaderboards and a member's own progress without exposing sensitive profile or learning data. Do not automatically grant moderation power based on points: use deliberate, reviewable appointment.

## Accessible, modern interaction contract

Target WCAG 2.2 AA with manual keyboard and screen-reader checks across sign-up, search, posting, course completion, RSVP, reporting and admin triage. Use semantic headings/landmarks and a skip link ([2.4.1](https://www.w3.org/WAI/WCAG22/Understanding/bypass-blocks)); all controls keyboard-operable with visible focus ([2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard), [2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible)); readable text and visible control boundaries ([1.4.11](https://www.w3.org/WAI/WCAG22/understanding/non-text-contrast.html)); reflow at 320 CSS pixels ([1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)); and 24×24 CSS-pixel pointer targets or permitted spacing equivalents ([2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)). Announce search counts, saved progress, RSVP and moderation outcomes as status messages ([4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)). Use APG [disclosure navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) rather than application-style ARIA menus for ordinary site links; respect dialog focus and Escape behavior ([APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)). Offer reduced motion for optional celebration ([2.3.3, AAA](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions)).

Information architecture: one stable primary navigation with purpose-named destinations (“Discussions,” “Courses,” “Events,” “Members,” “Resources”), one consistent search entry, and contextual subnavigation. Meaningful link labels, summaries and metadata help users predict a destination ([NN/g information scent](https://www.nngroup.com/articles/information-scent/)). Use helpful first-use/empty states rather than a blank feed. Performance should be measured rather than inferred from competitor claims: instrument p75 mobile/desktop [LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1](https://web.dev/articles/vitals) on the critical journeys.

## Sequence and release gates

**P0 — trustworthy core:** close email membership probing; repair enrollment, persistent completion/certificate and event RSVP; add minimal report queue/permissions; fix keyboard/focus/reflow blockers on those flows. Gate on end-to-end tests from a new member account, server-side credential tests, privacy tests and manual keyboard checks.

**P1 — coherent engagement:** unify navigation and actionable onboarding; expand cross-type search; make notification preferences real; add answer quality signals, badge award ledger and opt-in/opt-out rank controls. Gate on repeatable award/reversal tests and notification destination tests.

**P2 — rich, responsible play:** cohort challenges, team goals, per-skill paths, streaks with pause options, configurable rewards and analytics. Gate on abuse simulations, fairness/accessibility review and evidence that rewards improve completed learning/helpful answers rather than just post volume.

Do not interpret this as a claim that vendor features, accessibility or performance have been independently verified. The strongest differentiator for Forge is a reliable learning-to-community loop, not matching each vendor's feature count.
