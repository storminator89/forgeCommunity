# Chat unread state

`ChatReadCursor` has one row per `(userId, channelId)` and no role key. A missing row means the room has never been visibly opened, so old room history does not light up as unread. A row with a null position means the room was opened empty. Once a message is actually shown at the tail of a focused, visible conversation, the client sends only its ID; the server resolves its `(createdAt, id)` pair and advances the cursor with a conditional update. An older device cannot move it backward. The database removes cursors when their user or channel is deleted.

`GET /api/chat/channels` returns a boolean `hasUnread` on each channel. It uses the existing bounded channel list plus one account-scoped SQL query over cursor rows, rather than a query for every room. The three message-existence branches keep greater-timestamp and equal-timestamp lookups usable with the `(channelId, createdAt, id)` index. The SQL repeats the messages API's public-or-member access rule, so an admin-listed but unjoined private room cannot expose unread state. Own messages are excluded. Mark-read independently rechecks message access and that the supplied message belongs to the room. Client channel data is remounted on account or role changes. While visible and online, the channel list refreshes at most once every 30 seconds, with single-flight requests and 30/60/120-second failure backoff; hidden and offline views pause. A list that no longer includes the active private room immediately clears its content. Stale list responses cannot restore locally revoked rooms, and a stale false read acknowledgement cannot clear a newer unread dot. A stale true may conservatively keep a dot lit until the next refresh.

The page marks read only when the latest persisted message's bottom is in the visible log, the reader is at the tail, the page is focused and visible, and no newer sync pages remain. An empty room is initialized only after its initial page has loaded and its log is visible. A hidden tab, mobile channel list, older scroll position, or still-paged burst does not advance the cursor. The dot has a short accessible name and no count.

Unread uses the same `(createdAt, id)` order as chat pagination. Normal Prisma SQLite writes store canonical ISO timestamps; PostgreSQL stores native timestamps. SQLite's `CURRENT_TIMESTAMP` default has a different text format, so a direct SQL writer using that default can misorder against Prisma-written values until the chat history storage contract is normalized. This feature does not claim lossless delivery across PostgreSQL late commits: a delayed older-timestamp message can commit after a newer cursor has advanced and be missed, as documented in `chat-pagination-performance.md`. A monotonic commit sequence or overlap reconciliation would be a separate change.
