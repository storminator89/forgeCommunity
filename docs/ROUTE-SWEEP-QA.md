# App page-by-page browser sweep

This is an additive, disposable CI Playwright review lane. `e2e/route-sweep-manifest.ts` has one explicit case per current `app/**/page.tsx` file; `__tests__/route-sweep-manifest.test.ts` fails when a page is added or removed without updating that inventory. The browser test is picked up by the existing `test:browser` command and CI screenshot artifact glob. The CI workflow itself is unchanged. The inventory assumes removal of the unreachable `app/projects/[id]test/page.tsx` route in the same integration.

The 34-page inventory has **32 rendered-page checks and 2 redirect-only checks** (`/logout` and `/courses/[courseId]`). The route tests run at desktop 1280px and mobile 320px. They assert the expected settled h1, exactly one main and skip target, document/body width without page-wide overflow, first-Tab skip-link keyboard focus and visible focus outline, and skip-link activation. Data-driven pages additionally wait for a successful page API response and the loading state to clear, or for an account-specific/synthetic success marker. Each case saves a full-document PNG named from its source file. A redirect PNG shows its destination, not the fleeting redirect page. The app uses some independently scrollable panels, so a document PNG does not capture every scrolled panel state.

All accounts are newly registered `example.test` users in the explicitly disposable SQLite browser database. Staff roles are assigned only there. Seven dynamic pages render with narrowly intercepted **synthetic API responses**: course contents; article read and both article edit URLs; project detail; resource detail; certificate verification. These show page structure and interaction affordances but do not prove those APIs' authorization, real persistence or full-stack success paths. Profile uses a disposable account instead. Drafts, notifications, and learning goals are empty for the new account. Other directory pages use the browser job's **shared, synthetic disposable database**, which is also populated by other browser suites. Their contents and screenshots can vary with suite order and are not stable empty-state baselines. No fixture URL, screenshot filename, or fixture body contains a password, token or real user record.

The old `app/projects/[id]test/page.tsx` source did not provide a distinct reachable URL: its generated route pattern collided with `/projects/[projectId]`. It is removed rather than claiming a handoff the browser cannot prove. The normal project detail page remains covered by a synthetic project heading check.

Run the focused source check with `npx jest __tests__/route-sweep-manifest.test.ts --runInBand`. The browser suite requires the existing CI setup: a production build, official Playwright Chromium, and `BROWSER_QA_DISPOSABLE_DB=1` with `DATABASE_PROVIDER=sqlite` and an absolute `DATABASE_URL` whose basename is `forge-browser-qa.db`. In that setup, `npx playwright test e2e/route-sweep.pw.ts --project=desktop-chromium --project=mobile-320-chromium` runs just this sweep. The existing full `npm run test:browser` also picks it up.

Passing this automated sweep is **not** a WCAG 2.2 AA audit or visual sign-off. Human review of each PNG and independently scrollable panel, 375/414/768px reflow, dark mode, contrast, 200% zoom, reduced motion, longer German strings, and relevant role/empty/loading/error permutations remain release work. Full-stack browser coverage of the seven mocked dynamic routes remains a gap until independently verified on the exact CI commit SHA.
