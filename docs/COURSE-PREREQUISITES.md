# Course learning prerequisites

An author can require completion of up to 20 earlier leaf contents before a later leaf opens. The private course draft stores optional `prerequisiteIds` on each content in the existing schema-version-1 payload; older publications with no field have no prerequisites. A save and a publish validate unique same-course IDs, leaf-only dependencies, depth-first outline order, no dangling reference, and no cycle. Reordering across an edge fails validation. Deleting a referenced content is rejected with a prompt to explicitly remove its edges first; deletion never silently removes a learner lock. Review flags prerequisite changes before publication.

The active `CoursePublication.payload`, not the saved draft or browser state, is the path authority. An enrolled learner receives the full outline and missing-prerequisite titles, but a locked row has no lesson body, quiz questions, or content-version token. New progress and quiz submissions return 423 while locked; a stale publication returns 412. Idempotent replay of an already recorded quiz result keeps its existing behavior. Inline course images are readable only when a published, unlocked lesson references them. An active published cover remains public. H5P playback and asset requests recheck the current account, role, enrollment, active reference and path; a package reused by another unlocked reference remains readable. GET and HEAD use the same checks.

Current-revision leaf completions remain stored across a dependency edit. The effective completed set excludes a leaf while any prerequisite in its chain is incomplete; when the upstream leaf is completed again, the still-current historical downstream completion becomes effective again. Course completion and rewards follow the effective set. Issued certificates remain historical records and valid downloads. Assignment completion can join this set when the manual-grading package is integrated; assignment learner GET and new POST must call `assertCurrentPrerequisites(tx, userId, courseId, contentId, publicationId)` in the same serializable transaction after enrollment and current-publication checks. Cohort analytics can evaluate many learners efficiently with `prepareCoursePath(nodes)(rawCompletedIds)`.

## H5P asset capability boundary

H5P's sandbox omits app cookies, so each asset URL carries a two-hour, package-bound v2 bearer token. AES-GCM encrypts the actor ID and time bounds; the URL does not expose the actor ID in plaintext. Each GET, HEAD and range request decrypts the actor and rechecks that actor's *current* account, role and path access before reading bytes. Losing enrollment, a prerequisite unlock, ownership or administrator status stops an existing token from working on the next request. A person holding a copied token can still use it while its named actor remains authorized, up to expiration. Do not treat it as proof that the requester is that actor; avoid leaking the URL through logs or referrers. The response remains `private, no-store` with a restrictive CSP and no-referrer policy. Legacy v1 tokens are rejected after deployment; an open player must reload to obtain v2.
